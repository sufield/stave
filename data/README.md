# data/

Static reference data consumed by Stave at build time or runtime. None of this is generated — each file is maintained by hand and updated when upstream sources change.

## Directory Layout

```
data/
├── alternatives/       Prowler check inventories for coverage math
├── frameworks/         Compliance framework checklists for gap analysis
├── iamauth/            AWS IAM authorization reference per service
├── deprecation-calendar.yaml   Engine/TLS/artifact EOL dates
└── services.yaml       AWS service registry
```

## alternatives/

Declarative inventories of checks shipped by external tools (currently Prowler). Each YAML lists one tool's check IDs for one domain. The Makefile copies these into `internal/adapters/coverage/embedded/` at build time so they're baked into the binary.

Used by:
- `stave catalog gaps --checklist` coverage aggregation (denominator for "N of M checks covered")
- `internal/tools/genmethodologycoverage/` doc generation

Update when Prowler adds, removes, or renames checks. Source: `prowler-cloud/prowler` upstream master.

## frameworks/

Compliance framework checklists in a flat YAML format (`standard:` + `checks:` list). Each check has an `id`, `service`, `description`, and `reference`.

| File | Framework |
|------|-----------|
| `cis-aws-v3.yaml` | CIS AWS Foundations Benchmark v3.0 |
| `csa-ccm-v4.yaml` | CSA Cloud Controls Matrix v4 |
| `csa-aicm-v1.1.yaml` | CSA AI Controls Matrix v1.1 |
| `aws-irp.yaml` | AWS Incident Response Playbook |
| `aws-security-specialty.yaml` | AWS Security Specialty exam domains |
| `saa-c03-security.yaml` | SAA-C03 security domain |
| `prowler-aws.yaml` | Prowler AWS full check inventory |
| `securityhub-ai-best-practices.yaml` | Security Hub AI best practices |
| `aisvs-infra.yaml` | AI SVS infrastructure controls |
| `ttc-aws.yaml` | Time-to-Compromise kill-chain coverage |

Used by: `stave catalog gaps --checklist <file>` and `internal/tools/compliance-diff/`.

## iamauth/

Per-service JSON files from the AWS IAM authorization reference API (`servicereference.us-east-1.amazonaws.com`). Each file lists valid IAM actions, condition keys, resource types, and ARN formats for one AWS service. `index.json` is the service manifest with source URLs and modification timestamps.

452 files covering the full AWS service surface. No AWS credentials required to use — these are public reference data snapshots.

Used by: `internal/adapters/iamauth/` for IAM policy analysis and `internal/tools/triage/` for control triage.

Regenerated by: `internal/tools/geniamdata/`.

## services.yaml

Stave's explicit AWS service universe. Each entry has an `id`, `name`, `short_name`, `category`, and implicit status (`active`, `known_not_covered`, `out_of_scope`, `retired`, `preview`). Control counts are derived at runtime by joining against the catalog — never duplicated here.

Used by: `stave services` command.

## deprecation-calendar.yaml

Engine version EOL dates, deprecated TLS policies, and superseded AWS artifacts. Consumed by the quarterly deprecation audit engine (`internal/tools/quarterly/engine_deprecation.go`).

Update when AWS announces new deprecations or EOL dates.
