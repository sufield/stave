# Observation Contract

An observation is a point-in-time, normalized snapshot of asset state used by
Stave evaluation. Current schema: `obs.v0.1`.

Observations are generated by external extractors (any language producing
`obs.v0.1` JSON) or trusted pipelines. Do not hand-author production
observations — treat manual JSON edits as test-only. See
[Building an Extractor](extractor-prompt.md) for a jumpstart template.

## Snapshots as time-series

Each `.json` file in an observations directory is one point-in-time snapshot.
The engine reads all `.json` files in the directory in sorted-filename order
and evaluates controls across the time-series — enabling duration-based
detection ("bucket has been public for more than 24 hours") and drift
detection ("MFA was disabled between snapshot T1 and T2").

Each file carries its own `captured_at` and `generated_by` metadata. Files
sharing a `captured_at` trigger duplicate-timestamp warnings; the engine
expects distinct moments per file. Do not split one collection event across
multiple files — that is not the pattern the engine supports. To grow
observation history, add new files from new collection runs.

See [obs.v0.1 § File Layout](https://www.systeminvariant.dev/docs/reference/schema-obs#file-layout) for the
filename convention and an example directory.

## Versioning policy

- Contract version is encoded in `schema_version`.
- Breaking changes require a new schema version.
- Non-breaking additions may occur only when they do not invalidate existing consumers.

These are **stable contracts**. Once a field appears in a contract it is bound by these rules:

* **Additive change is always allowed.** Stave may consume new fields at any time. Producers and consumers MUST tolerate fields they do not recognize.
* **Removing or renaming a field is a breaking change.** It is not permitted on the existing contract. If unavoidable, the contract is re-released under a versioned ID alongside the original.
* **Tightening a field's type is a breaking change.** Widening (e.g., adding a new enum value) is allowed; narrowing requires the same versioned treatment as a rename.

Producers should be permissive about unknown fields so additive changes don't require an integrator rebuild.

`obs.v0.1` is treated as stable for all supported fields.

## Envelope

An observation file in a directory may take one of two shapes: a flat
per-timestamp JSON object (the fields below) or a bundle of multiple
snapshots wrapped as `{"schema_version":"obs.v0.1","snapshots":[…]}`.
The directory loader auto-detects the bundle shape and expands it
inline. Per-timestamp files run the strict `obs.v0.1` schema
(`additionalProperties: false`); bundle files route through the
bundle parser, which carries its own shape contract.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `schema_version` | string | yes | `"obs.v0.1"` |
| `captured_at` | string (RFC 3339) | yes | Snapshot capture time |
| `assets` | array | yes | Asset state objects (see below) |
| `generated_by` | object | no | Extraction metadata |
| `identities` | array | no | IAM identity objects (see below) |

### `generated_by`

| Field | Type | Description |
|-------|------|-------------|
| `source_type` | string | Extractor kind (`"aws-s3-snapshot"`, `"gcp.asset_inventory"`, `"custom.script"`) |
| `tool` | string | Tool name (`"stave-extract"`) |
| `tool_version` | string | Semantic version |
| `provider` | string | Cloud provider (`"aws"`) |
| `provider_version` | string | Provider API version |

## Asset structure

Each entry in `assets[]`:

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `id` | string | yes | Stable identifier (ARN or synthetic ID) |
| `type` | string | yes | Asset type (`"storage_bucket"`, pattern `^[a-z0-9][a-z0-9_.-]*$`) |
| `vendor` | string | yes | Cloud vendor (`"aws"`) |
| `properties` | object | yes | Domain-specific state (see field dictionary) |
| `source` | object | no | Source reference (`file`, `line`) |

---

## Identity structure

Each entry in `identities[]` (optional, used by ACL/policy controls):

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `id` | string | yes | Principal identifier (ARN, email) |
| `type` | string | yes | Identity type (pattern `^[a-z0-9][a-z0-9_.-]*$`) |
| `vendor` | string | yes | Cloud vendor |
| `properties` | object | yes | Identity-specific properties |

## Stability promise

These property namespaces are the stability surface. Fields within these
namespaces will not be removed or have their semantics changed without a
schema version bump.

### Storage domain (S3 + GCS)

- `storage.kind` — shared discriminator (`"bucket"`, `"access_point"`)
- `storage.access.*` — access control properties
- `storage.cdn_access.*` — CloudFront coupling facts (bucket-side view)
- `storage.controls.*` — safety net settings (PAB, uniform access)
- `storage.encryption.*` — encryption at rest and in transit
- `storage.versioning.*` — object versioning
- `storage.logging.*` — access logging
- `storage.object_lock.*` — immutability controls
- `storage.website.*` — static website hosting
- `storage.lifecycle.*` — data retention rules
- `storage.content.*` — content-level properties
- `storage.tags.*` — governance and classification tags
- `cdn.*` — CDN origin properties
- `s3_ref.*` — bucket reference (takeover detection)
- `s3_upload.*` — upload policy scope

### Identity domain (IAM)

- `identity.kind` — shared discriminator (`"account"`, `"user"`, `"password_policy"`)
- `identity.root.*` — root account properties
- `identity.console_access.*` — console login properties
- `identity.credentials.*` — credential lifecycle
- `identity.access_keys.*` — access key properties
- `identity.policies.*` — policy attachment properties
- `identity.password_policy.*` — password policy settings

### VPC domain

- `network.kind` — discriminator (`"vpc"`, `"security_group"`)
- `network.flow_log.*` — flow logging state
- `network.security_group.*` — security group rules and defaults

### EC2 domain

- `compute.kind` — discriminator (`"instance"`, `"snapshot"`)
- `compute.encryption.*` — EBS volume and snapshot encryption
- `compute.network.*` — public IP, IMDSv2

### RDS domain

- `database.kind` — discriminator (`"instance"`)
- `database.encryption.*` — storage encryption
- `database.access.*` — public accessibility, multi-AZ
- `database.backup.*` — automated backup state
- `database.logging.*` — audit log exports

### ELB domain

- `loadbalancer.kind` — discriminator (`"alb"`, `"nlb"`)
- `loadbalancer.encryption.*` — TLS version, HTTPS redirect
- `loadbalancer.logging.*` — access logging
- `loadbalancer.availability.*` — cross-zone balancing

### Kubernetes domain

- `rbac.kind` — discriminator (`"cluster_role"`, `"service_account"`)
- `rbac.*` — wildcard detection, token automount
- `network_policy.kind` — discriminator (`"namespace"`)
- `network_policy.*` — policy existence, default-deny
- `audit.kind` — discriminator (`"cluster"`)
- `audit.*` — API server audit logging
- `secrets.kind` — discriminator (`"cluster"`, `"pod"`)
- `secrets.*` — etcd encryption, environment variable secrets

## Global conventions

These conventions apply across every domain file. A field's domain file may
reference them but will not re-document them.

### Null vs empty

- **`null`** or field omitted: the derivation did not run, the precondition
  is not met, or the fact is not applicable (e.g., a bucket with no policy
  cannot have `policy_has_scoping_condition`).
- **`false`**, `[]`, `""`, `0`: the derivation ran and produced a negative
  or empty result.

Predicates that should only fire on unsafe grants gate on `op: present`
before checking value — the `CTL.S3.POLICY.SCOPING.001` and
`CTL.S3.POLICY.OBJECTSCOPED.001` pattern. This avoids firing on the
"not applicable" case.

### Raw vs effective signals

Some fields come in paired raw / Condition-aware variants:

- `storage.access.has_wildcard_principal` (raw — literal `Principal: "*"`) vs
  `storage.access.policy_is_effectively_public` (Condition-aware — reflects
  AWS `PolicyStatus.IsPublic`)
- `identity.policies.service_wildcards_granted` is currently raw; an
  effective variant may ship later as a peer field.

The raw signal matches Prowler/methodology-style detection. The effective
signal matches AWS-semantic evaluation. Controls choose whichever is
semantically appropriate; the split is documented per-field.

### Contract vs extractor scope

The contract documents **what each field means** and **the derivation rule**
an extractor must implement. The contract does **not** specify:

- Which AWS APIs the extractor calls to gather the source data
- How the extractor handles rate limits, pagination, or cross-region
  aggregation
- The extractor's own configuration or deployment model

If a future iteration needs a field that requires data the contract does
not currently carry, the contract extension is its own iteration before
any predicate or control work.

### Derived fields

Many fields are **derived** — the extractor parses a raw AWS response (or
joins multiple responses) and emits a named fact. Examples:

- `storage.access.has_wildcard_principal` — extractor parses bucket policy
  and sets the flag when `Principal: "*"` appears in any Allow statement.
- `identity.escalation.<technique>.present` — extractor checks the
  principal's attached policies against the specific technique's preconditions.
- `storage.exposure.has_public_access_point` — populated by a post-collection
  **derivation** (see `internal/core/evaluation/derive/`), not by the
  observer directly.

Derived fields are documented in the same tables as raw fields. The
derivation rule appears alongside the semantic definition.

## Cross-domain concerns

### Identity principals referenced from storage

Storage ACL and policy analysis references principals using the AWS ARN
string format. The `identity.*` observation (documented in
[identity.md](identity.md)) is separate from the string references embedded
in storage policies — the contract does not cross-link them. Future
derivations may join storage policy principals to `identity.*` assets;
that shape would land as a new derived field, not a contract cross-reference.

### CORS spans multiple services

CORS configuration appears under four different namespace prefixes depending
on which AWS service hosts it: `storage.cors.*` (S3 buckets), `api.cors.*`
(API Gateway v2), `cdn.response_headers_policy.cors.*` (CloudFront), and
`compute.function_url.cors.*` (Lambda Function URLs). [cors.md](cors.md)
documents the cross-service namespace as one unit.

### Reachability is cross-cutting

`reachability.*` fields attach to any asset type (S3 bucket, DynamoDB table,
Secrets Manager secret, etc.) and describe graph-traversal results. The
namespace lives in [reachability.md](reachability.md); individual storage
assets may have `reachability.*` fields populated even though the field
dictionary for `storage.*` does not re-document them.

Do not hand-author production observations. Generate observations using an

## Unused-field review (closed)

A grep of every control predicate's `field:` references against the
documented field set surfaced candidates that no control consumes. The
candidates were triaged into false-positives-by-category, intentional
diagnostic context, deferred-consumer (predicate landing later), and
genuine deletion candidates. The genuine-deletion slice has since been
deleted; the remaining entries are retained for the reasons listed
per category.

### False positives — not applicable

- **Envelope / observation structure** (`schema_version`, `captured_at`,
  `assets`, `identities`, `generated_by`, `properties`, `source_type`,
  `tool`, `tool_version`, `provider`, `provider_version`) — validated
  by JSON schema, not by predicates.
- **Asset-type discriminator strings** in the compliance-expansion table
  (`aws_apigateway_stage`, `aws_cloudtrail_trail`, `aws_dynamodb_table`,
  `aws_kms_key`, `aws_secretsmanager_secret`, etc.) — these are the
  `type` values of assets, referenced at the asset level, not via
  `properties.<field>` paths.
- **Fields reached via predicate aliases** (e.g., `s3.acl_readable_by_public`
  resolves internally to references on `storage.access.public_admin`,
  `authenticated_*`, `has_full_control_*`) — the alias short-circuits
  the literal-field grep but the fields are consumed.

### Intentional — diagnostic context, not predicate-gated

Per-technique escalation, reachability, and per-control finding-context
sub-fields are populated for **finding context** and surfaced in the
output, but predicates gate on adjacent fields only. Stripping them
would lose operator-facing remediation context without changing
detection behavior.

- `identity.escalation.<technique>.target_*`, `.permission_delta`,
  `.resource_scope`, `.reachable_managed_policies`,
  `.target_has_*`, `.invocation_*`, `.attachment_*`,
  `.has_create_version`, `.has_set_default`, `.has_activate_permission`,
  `.trust_pathway`, `.has_external_id_requirement`,
  `.endpoint_type`, `.runtime`, `.target_instance`,
  `.invocation_method`
- `identity.escalation.escalation_vector`, `.steps`, `.step_count`,
  `.target_admin_role` (`CTL.IAM.ESCALATE.CHAIN.001`'s diagnostic set —
  the control gates on `can_escalate_to_admin` only)
- `reachability.anonymous_path.path_summary`, `.auth_boundary_types`,
  `.inspection_boundary_types`, `.entry_point_type`,
  `.unresolved_reason`
- `reachability.anonymous_path.blocked_at.*`
- `reachability.exfiltration.compute_id`, `.egress_type`, `.vector`,
  `.target_data_classification`
- `reachability.sovereignty.resource_jurisdiction`,
  `.accessor_jurisdiction`
- `storage.alias`, `storage.bucket_name`, `storage.network_origin`,
  `storage.vpc_id` (single-region Access Point asset) — resource
  identity surfaced in findings; no predicate gates on them but AP
  findings lose actionability without them.
- `dns.hostname`, `dns.target_provider` — DNS record identity + provider
  attribution surfaced in `CTL.DNS.DANGLING.001` findings; predicate
  gates on `target_exists` / `target_owned` / `record_type`.
- `identity.trust.oidc.provider`, `.sub_claim_value` — diagnostic
  context for `CTL.IAM.TRUST.OIDC.001` findings (gate is
  `.sub_claim_scoped`).
- `identity.permission_categories` — diagnostic enumeration companion
  to `CTL.IAM.ROLE.CATEGORYMIX.001`'s `has_incompatible_categories`
  gate.
- `identity.role.cross_env.path_hop_count`, `.source_env`,
  `.via_bridge_role` — diagnostic context for
  `CTL.IAM.CROSS.ENV.PATH.001` findings (gate is
  `reachable_from_lower_env`).
- `backup.recovery_isolation.kms_key_account`, `.data_account` —
  diagnostic account-identity context for
  `CTL.BACKUP.RECOVERY.ISOLATION.*` findings (gate is
  `kms_same_account_as_source`).

### Consumers that landed

- `identity.policies.service_wildcards_granted` — consumed by
  `CTL.IAM.POLICY.SERVICEWILDCARD.001` (parameterized on
  `denied_service_wildcards`).
- `storage.public_access_block.block_public_acls`,
  `.ignore_public_acls`, `.block_public_policy`,
  `.restrict_public_buckets` (Access Point level) — consumed by the
  four `CTL.S3.AP.PAB.{BLOCKPUBLICACLS,IGNOREPUBLICACLS,BLOCKPUBLICPOLICY,RESTRICTPUBLICBUCKETS}.001`
  sub-flag controls, symmetric to the bucket-level `CTL.S3.PAB.*`
  family.

### Deleted as unused

The following fields had zero predicate consumers, zero alias-resolved
references, zero fixture population, and zero diagnostic-context role
for any shipping control. Removed from the contract in a pre-release
cleanup:

- `storage.visibility.public_read`, `.public_list`, `.public_write`,
  `.public_read_via_acl`, `.public_read_via_policy` — shadow
  namespace superseded by `storage.access.public_*`.
- `storage.cors.allows_wildcard_header`, `storage.cors.rules` —
  predicates consume `storage.cors.configured` and
  `storage.cors.allows_wildcard_origin` only.
- `identity.role.can_delete_all_backups` — never populated by any
  fixture; no control references it.
- `cryptography.key_concentration.service_count`,
  `.has_multi_region_replica` — `CTL.KMS.CONCENTRATION.*` gates on
  `.resource_count` and `.has_deletion_protection`; the two removed
  fields were unused.
- `cryptography.key_isolation.domain_count`, `.mixed_classification` —
  `CTL.KMS.ISOLATION.001` gates on `.is_exclusive_to_domain`; the two
  removed fields were unused.

**Mechanical grep methodology**: this list was produced by extracting
every `properties.X` reference from `controls/**/*.yaml`, comparing
against every documented field path in `docs/contract/*.md`, and
categorizing the gap. Alias-resolved references (`unsafe_predicate_alias`)
are not traced through their resolution; categorization has been
hand-checked against the alias expansions in
`internal/builtin/predicate/aliases.go`.
